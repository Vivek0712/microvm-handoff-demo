# microvm-handoff-demo: build spec

The repo demonstrates, on the live service, every way an orchestrator hands a task to an
AWS Lambda MicroVM through the microvm-ctl lease contract (0.3.0 from PyPI), with Step
Functions and Lambda durable functions side by side. Every number, log, history, and
screenshot under `results/` is captured from a real execution in account 643603452951,
us-east-1, profile `heisenberg`. Nothing is mocked; nothing is typed in by hand.

## Fixed names

| Thing | Name |
|---|---|
| Agent image | `demo-agent` (512 MiB, built from `agent/`, one version) |
| Step Functions stack, single lease | `mvm-demo-sfn` (state machine `mvm-demo-sfn-lease`) |
| Step Functions stack, Map fan-out with approval gate | `mvm-demo-sfn-map` (state machine `mvm-demo-sfn-map-lease`, SNS topic `mvm-demo-approvals`, SQS `mvm-demo-approvals-q` subscribed) |
| Durable stack | `mvm-demo-durable` (function `mvm-demo-durable-orchestrator:live`, SQS `mvm-demo-durable-approvals`) |
| CLI env for every command | `AWS_PROFILE=heisenberg MVM_REGION=us-east-1 MVM_ARTIFACT_BUCKET=microvm-ctl-artifacts-643603452951-us-east-1 MVM_BUILD_ROLE_ARN=arn:aws:iam::643603452951:role/microvm-ctl-build-role MVM_EXECUTION_ROLE_ARN=arn:aws:iam::643603452951:role/microvm-ctl-execution-role` |
| Lease policy for every scenario | budget 120 s, heartbeat 30 s, slack 60 s, `max_concurrency` 4, `max_vm_seconds` 3000, `approval_usd` 0.02 |

Account limits: memory quota 8 GB, RunMicrovm 1/s. Never run more than 8 x 512 MiB at once.
Terminate everything you launch; `mvm ls --all` must show no RUNNING/PENDING/SUSPENDED VMs
when a phase ends. Do not touch stacks or VMs whose names are not in the table above.

## Scenario matrix (both orchestrators unless noted)

| id | what it proves | task | expected |
|---|---|---|---|
| `single` | one lease: launch, /run, heartbeats, completion, terminate | 3 shell steps (`uname -m`, `python3 -c 'print(2+2)'`, `sleep 2`) | SUCCEEDED, `passed: true`, 3 steps, VM terminated |
| `parallel` | in-VM parallelism | 4 x `sleep 3` with `"parallel": true, "max_parallel": 4` vs the same 4 sequential | parallel wall time ~3 s vs ~12 s inside the VM (from the result's step durations) |
| `retryable-fail` | typed retryable failure and relaunch | `fail_after_s: 2` (raises `Injected`, retryable) | sfn: Lease -> Catch -> Reap -> TerminateStale -> Failed with the typed error in the output; durable: `lease_with_relaunch` attempt 0 and 1 both fail, outcome `status: failed, retryable: true, attempt: 1` |
| `hang` | budget timeout while the VM keeps heartbeating | 1 step then `hang_s: 400`, budget 60 s | sfn: States.Timeout -> Reap terminates the VM -> Failed; durable: CallbackTimeoutError -> terminate -> `status: timeout` |
| `fanout-4` | governed fan-out inside the plan | 4 shards, each 2 steps | plan: concurrency 4, 1 wave; all 4 done; Map/lease_map output has 4 results |
| `fanout-8` | fan-out in waves | 8 shards | plan: concurrency 4, 2 waves; 8 done; RunMicrovm throttling retries visible if they happen |
| `fanout-refused` | pre-flight refusal, nothing launched | 12 shards with `max_vm_seconds` 3000 (12 x 512 MiB x 180 s = 2160 VM-s passes, so use 40 shards: 7200 VM-s) | sfn: `mvm lease plan --shards 40` exits 2 and run.py refuses to start the execution (record the plan); durable: `lease_map` plan step returns `status: rejected`, zero RunMicrovm calls |
| `fanout-approved` | approval gate, approved | 6 shards with `approval_usd` 0.02 (sfn: `ApproveAboveShards` 4) | sfn: RequestApproval publishes to SNS with the task token; approver reads SQS and calls SendTaskSuccess; Fanout runs; durable: `approve` publishes callback id to SQS; approver calls SendDurableExecutionCallbackSuccess; `status: done` |
| `fanout-denied` | approval gate, denied | same as above, approver denies | sfn: SendTaskFailure -> Denied state, nothing launched; durable: SendDurableExecutionCallbackFailure -> `status: denied`, nothing launched |
| `cli-none` (CLI only) | the same image with no orchestrator | `mvm lease run demo-agent --kind none --wait` + `mvm watch` | done, heartbeats 0 |

Every scenario directory gets: the exact input, the full execution history (Step Functions
`get_execution_history` all pages; durable `get_durable_execution` + the events/ operations
listing the SDK exposes, via `aws lambda get-durable-execution` / `list-durable-execution-...`
whichever exists in this CLI version), a human-readable `history.txt` (event, name, timestamp,
delta from start), the output JSON, the VM's own log lines from `/aws/lambda-microvms/demo-agent`
filtered to that VM id, the orchestrator's CloudWatch log lines for that execution, and
`summary.json` with `{"scenario","orchestrator","status","expected","matches_expected":bool,
"start","stop","seconds_by_service","vm_ids":[...],"runmicrovm_calls":int,"notes":[...]}`.

## Benchmarks

`benchmarks/bench.py` runs `single` 5 times per orchestrator and `fanout-4` and `fanout-8`
twice each, timing only from the services' own timestamps (Step Functions
`describe_execution` startDate/stopDate; durable `get_durable_execution` start/stop; VM
`GetMicrovm` startedAt/terminatedAt for VM-seconds and cost at $0.0000350 per GiB-s ... use
`microvm.lease.VM_USD_PER_GB_S`). Output `benchmarks/results/bench.json`, `bench.svg`, and
`bench.png` (render SVG to PNG with headless Chrome:
`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --screenshot=... --window-size=...`).
Report p50 and max, VM-s, and USD per run. Never time from a poll loop.

## Rules

- Install nothing local into the deployed functions: `requirements.txt` pins `microvm-ctl[durable]>=0.3.0`
  and `sam build` uses Python 3.13 from `/private/tmp/claude-501/-Users-vivekrajaps-microvm-ctl/f2158993-27f3-4ba8-a3d9-31b91885a0a7/scratchpad/dvenv/bin` on PATH with `PIP_NO_CACHE_DIR=1`.
- Generate ASL with `mvm lease asl` / `microvm.integrations.stepfunctions`; do not hand-write states.
- Orchestrator roles need `lambda:RunMicrovm`, `lambda:GetMicrovm`, `lambda:TerminateMicrovm`,
  `lambda:ListMicrovms`, `lambda:PassNetworkConnector` on `arn:aws:lambda:*:aws:network-connector:aws-network-connector:*`,
  and `iam:PassRole` on the agent execution role; the agent execution role needs logs on
  `/aws/lambda-microvms/*` and `/aws/lambda/microvms/*`, `states:SendTask*` / `states:SendTaskHeartbeat`
  or `lambda:SendDurableExecutionCallback*`.
- Never print or store credentials. `results/` contains only ARNs, ids, timestamps, and log text.
- Every claim in README.md and RESULTS.md must point at a file under `results/` that shows it.
- ruff clean (line 110), `python3 -m py_compile` on every .py, `sam validate` / `aws cloudformation validate-template` on every template.
